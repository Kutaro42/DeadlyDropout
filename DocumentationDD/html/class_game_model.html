Detailed Description

Root model aggregating persistent game-session data (MVC Model layer).

Owns exactly one PlayerModel and one LevelModel at any time. It does NOT own game logic — that responsibility belongs to GameController and LevelController. Keeping data and logic separate means the model can be serialised, reset or inspected by tests without running the game loop.

The boss pointer is kept here (rather than only in LevelModel) so that GameController can query boss state for music/UI purposes without having to search the enemy list every frame.

void GameModel::initPlayer ( Vector2f spawnPos)

Creates (or resets) the player at the given spawn position.

Called by GameController after LevelBuilder has populated the level so that the spawn coordinate is valid. Also wires the level's key-obtained signal to GameModel::obtainKey so the player inventory stays in sync.

Parameters
spawnPosWorld-space position where the player should appear.
